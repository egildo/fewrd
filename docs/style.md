# Writing style

How fewrd's documents are written. The base is [Google's developer documentation style guide](https://developers.google.com/style), with its [Markdown style guide](https://google.github.io/styleguide/docguide/style.html) for the source. Procedures, the numbered steps of a tutorial or a how-to, follow [Microsoft's rules for procedures](https://learn.microsoft.com/en-us/style-guide/procedures-instructions/): a numbered list, one action to a step, in the imperative, with any condition or place before the action.

Where those guides and this page disagree, this page wins. These are the only exceptions.

## British spelling

*normalise*, *colour*, *centre*. Code keeps its own spelling wherever it appears: the CSS property is `color`.

## No serial comma

"tags, rows and nodes", not "tags, rows, and nodes". A comma before *and* joins two clauses, never the last two items of a list.

## The closed vocabulary

One name per thing, the name the code uses, and only names the [glossary](glossary.md) holds. A new term amends the glossary first; see [A closed vocabulary](principles.md#a-closed-vocabulary).

## One paragraph to a line

Each paragraph, list item and table row is one line of source, however long. Google's 80-column limit does not apply.
